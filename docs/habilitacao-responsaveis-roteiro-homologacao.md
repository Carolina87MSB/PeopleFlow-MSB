# Roteiro de homologação para o RH — habilitação, administração de treinamentos, ausências e reposições

**Quando usar:** depois da publicação coordenada (ou em ambiente de teste). **Dados:** use sempre treinamentos marcados como **"Treinamento de homologação/teste"** (só o RH marca; ficam fora de indicadores, histórico oficial e avaliações). As **habilitações** são reais (não têm marca de teste): habilite apenas quem de fato será responsável. Não crie colaboradores fictícios.

**Pessoas necessárias:** você (RH), 1 colaborador a habilitar como **responsável (A)**, 1 colaborador habilitado como **instrutor interno (B)**, 1 colaborador habilitado de **outra área (C)**, 1 gestor de A, 3–4 participantes, e, se possível, 1 pessoa com **menos de seis meses** e sem acesso.

Marque ✓ / ✗ e anote observações em cada linha.

## 1. Habilitações (RH)
| # | Passo | Esperado | Resultado |
|---|---|---|---|
| 1.1 | Treinamentos → **Habilitações** (botão no alto da Agenda) | Abre a lista de habilitados, o formulário e o histórico de revogações | |
| 1.2 | Habilitar **A**: escolher o colaborador, conferir a gestão sugerida, preencher a **referência** (e-mail da liderança) | Aparece em "Habilitados" com área, gestão, data, **quem habilitou** e a referência | |
| 1.3 | Tentar habilitar sem a referência | O botão não habilita | |
| 1.4 | Tentar habilitar A de novo | Recusado ("já está habilitado") | |
| 1.5 | Habilitar **B** e **C** (C em outra gestão) | Ambos listados | |
| 1.6 | (Opcional) Habilitar pessoa **sem conta e com menos de seis meses** | Pede para marcar "Criar acesso ao portal (somente Treinamentos)"; após habilitar, a pessoa entra e vê **só** "Meus treinamentos" e Treinamentos (sem AVD e sem outros módulos) | |
| 1.7 | Entrar como o **gestor de A** → Treinamentos | Botão "Responsáveis habilitados" mostra A e B **somente leitura**; **sem** botão "Registrar treinamento" | |

## 2. Responsável e instrutor administram (e só o seu treinamento)
| # | Passo | Esperado | Resultado |
|---|---|---|---|
| 2.1 | O **RH registra** o treinamento de teste (marcando "Treinamento de homologação/teste", opção só do RH) com **A como responsável principal e B como instrutor interno** | Treinamento planejado; responsável e instrutor identificados. (Depois, A registra um treinamento próprio apenas para conferir que o botão "Registrar treinamento" aparece para ele e que ele já nasce como responsável principal; cancele-o em seguida.) | |
| 2.2 | A e B (cada um, em seu login) abrem o treinamento | Ambos veem os botões de administração (turma, iniciar, QR, presença, evidências, conferir/concluir) | |
| 2.3 | **C** abre a lista e tenta acessar o treinamento de A | **Não vê** o treinamento (nem turma, evidências ou avaliação) | |
| 2.4 | O **gestor de A** abre o treinamento | Vê (acompanha) mas **sem** botões de administração e com o aviso "Você acompanha este treinamento" | |
| 2.5 | A tenta trocar o **responsável** na edição | O campo está travado; a orientação diz que a troca é do RH | |
| 2.6 | Treinamento com **instrutor externo**: cadastrar o nome em "Instrutor / instituição externa" | O instrutor externo **não** precisa de login; o responsável administra e conclui | |
| 2.7 | Um **instrutor interno sem habilitação** (se houver) | Não administra e não vê o módulo | |

## 3. Execução, presença e QR
| # | Passo | Esperado | Resultado |
|---|---|---|---|
| 3.1 | A inclui participantes e **inicia** | Status "Em andamento" | |
| 3.2 | A gera o **QR**; participantes confirmam a própria presença | Presença "QR" com data/hora | |
| 3.3 | B (instrutor) registra presença **manual** de um participante (com justificativa) | Registrado como "Manual" | |
| 3.4 | Marcar um participante como **Ausente** (motivo "afastamento/licença") | Aparece "Sem encaminhamento" | |
| 3.5 | Tentar **retirar** o ausente da turma | Bloqueado (usa-se encaminhamento/dispensa) | |

## 4. Ausência, reposição e dispensa
| # | Passo | Esperado | Resultado |
|---|---|---|---|
| 4.1 | "Justificar e encaminhar" no ausente → **Haverá reposição**, com data prevista | Mostra "Reposição pendente · prevista para…" | |
| 4.2 | Segundo ausente: encaminhar **sem** data | "sem data prevista" | |
| 4.3 | A tenta **dispensar** | A opção não aparece para A (só o RH) | |
| 4.4 | **Conferir e concluir** com um participante ainda **pendente** de presença | Lista "Impede a conclusão" e o botão fica desabilitado | |
| 4.5 | Resolver a presença pendente e conferir de novo | "Pronto para concluir" + bloco **"Permanece pendente depois de concluir"** (reposições, reação, eficácia) | |
| 4.6 | **Concluir** (por A ou B) | Status "Concluído"; a Lista de Presença é gerada; fica registrado quem concluiu, data e horário | |
| 4.7 | Treinamento → **Pendências** (RH, o gestor e A). Como o treinamento é de teste, o **RH marca "Incluir treinamentos de teste (homologação)"** (os demais não veem testes) | Os ausentes continuam listados (com a marca TESTE) (a conclusão **não** os regularizou), vinculados ao treinamento original | |
| 4.8 | A **programa a reposição** (Faltantes e reposições → "Agendar treinamento para faltantes") para um deles | Situação passa a "Reposição programada"; o treinamento original permanece concluído | |
| 4.9 | Executar a reposição e concluí-la | O participante sai da lista de Pendências; no original ele continua "Ausente" (histórico preservado) | |
| 4.10 | **RH dispensa** o outro ausente (com justificativa) | Sai da fila; o registro mostra "Dispensado pelo RH"; não dá para alterar depois | |

## 6. Avaliação de Reação (anonimato)
| # | Passo | Esperado | Resultado |
|---|---|---|---|
| 6.1 | Em treinamento **oficial** (a reação não existe para testes), participantes respondem 1, depois 2 respostas | A, B, o gestor e o RH veem **quem respondeu**, mas **nenhuma média** e nenhuma nota | |
| 6.2 | 3ª resposta | Aparecem as **médias consolidadas**; nunca a nota de uma pessoa | |
| 6.3 | C tenta abrir a avaliação de A | Não tem acesso | |

## 7. Revogação e transferência
| # | Passo | Esperado | Resultado |
|---|---|---|---|
| 7.1 | Ter um treinamento **planejado/em andamento** de A. **Revogar** a habilitação de A (com motivo) | Mostra os **treinamentos pendentes** de A; A perde os poderes **agora** (sem esperar) | |
| 7.2 | A abre o portal | Não administra mais; continua vendo **Meus treinamentos** | |
| 7.3 | Pendências (com "Incluir treinamentos de teste" marcado, se o treinamento for de teste) → "Treinamentos sem responsável habilitado" | O treinamento de A aparece como "Responsável sem habilitação ativa" | |
| 7.4 | **Transferir** para B (motivo e tipo) | O novo responsável passa a administrar; quem registrou e o instrutor não mudam | |
| 7.5 | Tentar transferir para quem não é habilitado nem do RH | Recusado | |
| 7.6 | Treinamento **concluído** de A | Permanece íntegro (evidências, lista, presenças) | |
| 7.7 | Treinamento → "Mais detalhes" (RH) | Mostra o **histórico de transferências** | |
| 7.8 | Habilitações → Histórico de revogações | A revogada aparece com motivo, quem e quando | |

## Demonstração local (antes da publicação)

Para ver as telas reais com dados **fictícios** (banco em memória, nada toca o Supabase de produção):

1. `cd tests && npm run demo:api` (servidor local, porta 5190; abre já com os cenários executados).
2. Na raiz: `npx vite --config tests/demo/vite.demo.config.mts` e abrir `http://localhost:5191/tests/demo/index.html`.
3. No alto: **Entrar como** (RH, gestoras, colaboradoras habilitadas, participantes), **Reiniciar do zero** ou **Carregar demonstração completa**. A página *Resultado da homologação* lista, por cenário, o esperado × verificado.
4. Verificação por script, sem interface: `cd tests && npm run demo:verificar` (gera `tests/demo/resultado-homologacao.json`).

O menu lateral da demonstração é simplificado; as telas do módulo (Treinamentos, Treinamento, Meus treinamentos) são as reais. A conferência no celular e a do menu real continuam no roteiro acima.

**Histórico de ações:** cada treinamento tem o cartão *Histórico de ações* (botão *Ver histórico*), com quem fez cada ação e quando (RH, quem administra e a liderança que acompanha).
